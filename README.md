# Ultra-lightweight sleep stage classification on a microcontroller

Code for the paper *Ultra-Lightweight Sleep Stage Classification on a Microcontroller: Hardware-Validated
Compression and a Controlled Evaluation of Teacher-Assistant Distillation* (Pham, Tran, Nguyen, Do and Lin,
Scientific Reports, under review).

- **Code (this repository):** DOI `[to be added]`
- **Results, measurement logs and checkpoints (Zenodo dataset):** DOI `[to be added]`

The repository contains everything needed to reproduce the reported results: the model code, the Colab notebooks
that prepare the data, train all models and compute the statistics, the scripts that generate every table of the
paper and the Supplementary from the exported results, and the microcontroller firmware with its quantization and
measurement scripts.

## Models

| Tier | Architecture | Parameters (inference) |
|---|---|---|
| Teacher | two-branch Inception CNN (EOG 51/101, EEG 15/31) + 3-layer Transformer | 2,558,469 |
| Linear Assistant | two-branch CNN (EOG 51, EEG 15) + 2-layer linear attention | 290,501 |
| Edge Student | two-branch depthwise-separable CNN + GRU (32) | 17,318 |

Input: 21 epochs of 30 s (EEG Fpz-Cz and Pz-Oz, horizontal EOG; 100 Hz), centre epoch classified into W, N1, N2,
N3, REM. The Edge Student is causal (the centre-epoch output depends on that epoch and the 10 preceding ones).

## Repository layout

```
model_v11/        model definitions (Teacher, Linear Assistant, Edge Student)
losses_v11.py     focal loss and distillation loss
tools/
  nbsrc/          Python modules used by the notebooks: prep.py (data), skd.py (training, statistics),
                  cka.py, xai.py (attribution), qsim.py (quantization simulation)
  build_notebook.py   builds the notebooks in notebooks/ from tools/nbsrc and model_v11 (single source of truth)
  make_results_tables.py, make_supplementary.py, run_hybrid_local.py, arm_names.py
                  tables of the paper and the Supplementary from the exported results
  arch_params.py  architecture numbers (layers, channels, kernels, parameter counts) from the model code
  smoke_*.py      end-to-end tests of the notebooks on synthetic data (CPU)
notebooks/        Google Colab notebooks (generated by build_notebook.py)
hardware/         ESP32 / ESP32-S3 firmware, quantization export, measurement and table scripts
```

The notebook instructions (markdown cells) and some code comments in `model_v11/` are in Vietnamese; the code
itself, the modules in `tools/nbsrc/` and this README are in English.

## Requirements

Python 3.11; see `requirements.txt`. The notebooks run on Google Colab (GPU) and install their own dependencies.
Quantization uses ESP-PPQ 1.3.9, which needs Python <= 3.12; the quantization notebook creates a separate Python
3.12 environment for it. Firmware: ESP-IDF 5.4.4 and ESP-DL 3.3.10 (pinned in `hardware/firmware/main/idf_component.yml`).

## Data

The datasets are public and are downloaded by the notebooks:
Sleep-EDF Expanded and HMC (PhysioNet), DREAMS (Zenodo). No raw recordings are redistributed here.

## Reproducing the results

### 1. Training and evaluation (Google Colab)

Run the notebooks in this order; each one saves its results on Google Drive and can be resumed.

| Notebook | Produces |
|---|---|
| `R2_subject_level_rerun.ipynb` | Sleep-EDF preprocessing, subject-level folds, all training variants, parameter / MAC counts, primary statistics |
| `R2_hmc_crossdataset.ipynb` | HMC in-domain training and zero-shot transfer Sleep-EDF <-> HMC |
| `R2_seed_robustness.ipynb` | Edge Students with training seeds 43 and 44 |
| `R2_cka_v2.ipynb` | linear CKA with random-initialization baselines, UMAP |
| `R2_xai_dreams.ipynb` | attribution analysis on DREAMS with reference maps and random networks |
| `R2_hw_export.ipynb` | deployed model, calibration epochs and the 100 test windows for the chip |
| `R2_quant_eval.ipynb` | quantized vs. FP32 on the complete test set; the 500 test windows for the chip |
| `R2_export_numbers.ipynb` | `results_export.zip` with all results and predictions (the content of the Zenodo dataset) |

To rebuild the notebooks from the sources: `python tools/build_notebook.py . tools/nbsrc notebooks <code_dir>`.

### 2. Tables from the exported results (no GPU needed)

Download the Zenodo dataset (or use your own `results_export.zip`) and build the code directory once:

```
python tools/build_notebook.py . tools/nbsrc notebooks build/code
export PYTHONPATH=build/code            # Windows: set PYTHONPATH=build\code
python tools/run_hybrid_local.py <data> <data>/results/local_recomputation        # primary statistics
python tools/make_results_tables.py <data> <data>/results/local_recomputation/primary_hybrid_cluster_bootstrap.csv tables/
python tools/make_supplementary.py  <data> <data>/results/local_recomputation/primary_hybrid_cluster_bootstrap.csv supplementary/
```

`<data>` is the folder of the Zenodo dataset (it contains `results/`, `runs/`, `runs_hmc/`). The scripts check
every qualitative statement of the paper against the data and stop if one does not hold.

| Paper | Source |
|---|---|
| Table 1 (parameters, MACs) | `R2_subject_level_rerun` -> `results/param_counts.csv` |
| Tables 2–5 (Sleep-EDF performance, variants, contrasts, per-stage F1) | `make_results_tables.py` |
| Table 6 (HMC, zero-shot) | `make_results_tables.py` (from `R2_hmc_crossdataset` results) |
| Table 7, Fig. 1 (CKA, UMAP) | `R2_cka_v2`; table by `make_results_tables.py` |
| Table 8, Fig. 2 (attribution on DREAMS) | `R2_xai_dreams`; table by `make_results_tables.py` |
| Table 9 (hardware) | `hardware/make_hw_tables.py` |
| Table 10, rows "Ours" | `make_results_tables.py` |
| Figs. 3–5 (architectures) | numbers from `tools/arch_params.py` |
| Training seed, quantization results (Results text) | `R2_seed_robustness`, `R2_quant_eval`; `make_results_tables.py` |
| Supplementary Tables S1–S21, Supplementary Data 1–2 | `make_supplementary.py` |

### 3. Microcontroller deployment (`hardware/`)

Copy `hardware/inputs/`, `hardware/logs/` and `hardware/build_artifacts/` from the Zenodo dataset into `hardware/`.

```
python hardware/quantize_export.py --target esp32      # or esp32s3; writes hardware/firmware/model/ + simulation references
#   (to keep the published firmware files, use --sim-only: re-quantizes, checks every exponent, rewrites only the references)
. $IDF_PATH/export.sh                                   # ESP-IDF 5.4.4
cd hardware/firmware && idf.py set-target esp32 && idf.py build && idf.py -p <PORT> flash && cd ../..
python hardware/host_run.py --port <PORT> --target esp32 --map hardware/firmware/build/sleep_staging_r2.map
python hardware/host_run.py --port <PORT> --target esp32 --set _500 --stress 0
python hardware/make_hw_tables.py hw_tables/          # Table 9 from the runs listed in logs/OFFICIAL_RUNS.json
```

The exported files of the published runs are in `hardware/firmware/model/` (ESP32-S3) and
`hardware/firmware/model_esp32/` (ESP32); the firmware embeds `firmware/model/`, so copy `model_esp32/` there to
build for the ESP32 (or re-export with `quantize_export.py`). The byte size of the exported INT8 files can differ by
a few tens of bytes between exports with identical quantization parameters (serialization order); the quantization
parameters themselves are checked by `--sim-only`.

The firmware runs the depthwise and pointwise convolutions in INT8 (ESP-DL) and everything else in FP32. `host_run.py`
sends each test window over UART (460,800 baud), compares the chip with the PyTorch FP32 model and with the PC
simulation of the quantized model, repeats three windows, runs a continuous-operation test, and stores the raw
serial log and `results.json`. `test_host_fake_device.py` tests the protocol without a board.

### 4. Tests

`tools/smoke_*.py` run the notebooks end to end on small synthetic data on a CPU (one epoch per model), including
the quantization notebook with a real ESP-PPQ quantization.
